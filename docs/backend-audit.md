| POST | `/api/admin/login` | `password` | 管理员登录，消费返回的 `token` |

## 4. 第一版新增接口建议

以下是待团队确认的设计，不代表已经实现。不先锁定框架、数据库或认证供应商，优先复用现有服务。

| 优先级 | 接口建议 | 需要解决的问题 |
| --- | --- | --- |
| P0 | 注册、登录、退出、密码重置接口 | 普通用户身份、会话生命周期、找回账号；路由随认证方案确定 |
| P0 | `GET /api/me`、`PATCH /api/me` | 获取个人资料、修改昵称；用户身份从服务端会话取得 |
| P0 | `GET /api/me/progress` | 返回到访节点、已解题目、最近节点和服务端更新时间 |
| P0 | `POST /api/me/visits` | 提交合法节点 ID，幂等更新个人到访状态；与全站访问统计分开 |
| P0 | `GET /api/quiz/questions` | 提供可作答题目及题库版本；正式作答前不提供标准答案字段 |
| P0 | `POST /api/me/quiz-attempts` | 提交题目 ID、版本、选项和请求标识，服务端判题并保存记录 |
| P0 | `POST /api/me/progress/import` | 用户确认后导入游客记录，重复请求不产生重复记录 |
| P0 | `GET /api/me/favorites` | 获取账号收藏 |
| P0 | `PUT /api/me/favorites/:nodeId`、`DELETE /api/me/favorites/:nodeId` | 收藏与取消收藏，重复操作结果稳定 |
| P1 | `GET /api/me/achievements` | 服务端计算并返回印章解锁状态 |
| P1 | `GET /api/me/messages` | 查看本人留言和审核状态，复用现有留言模型 |

### 游客记录合并的边界

- 到访节点和收藏可以校验 ID 后合并去重，不以客户端提交时间覆盖服务端记录。
- 当前游客答题只保存“答对的题目 ID”，没有作答选项，无法追溯验证正确性。
- 建议将旧答题 ID 导入为“历史学习标记”，与“服务端已验证答题结果”分开；若印章采用服务端校验条件，则旧标记不能直接用于授予资格，可提示重新作答。
- 新版游客作答可保留题目版本、选项和请求标识，在用户同意导入时由服务端重新判定。
- 最近浏览位置需明确选择规则；退出或切换账号时清理账号缓存，防止上一位用户的数据显示给下一位。

## 5. 数据模型建议

这些是逻辑实体，不要求立即创建新表或迁移现有生产数据。

- 用户及认证身份：稳定用户 ID、昵称、创建时间；凭证交给选定认证机制管理，不保存明文密码。
- 个人到访：用户 ID、节点 ID、首次和最近到访时间；用户与节点组合唯一。
- 作答记录：用户 ID、题目 ID、题库版本、选项、服务端判定结果、时间、幂等标识。
- 收藏：用户 ID、节点 ID、创建时间；用户与节点组合唯一。
- 学习状态：最近节点、更新时间；完成数量优先从有效记录计算，避免多处计数不一致。
- 留言：复用现有模型，增加可选用户关联；既有匿名留言不强行绑定给个人。
- 成果：可从进度推导；如需保存刻印内容或授予时间，再新增成果记录。
- 管理审计：记录操作者、动作、对象与结果，不记录密码、会话令牌等敏感值。

## 6. 黄好的执行顺序

1. 获取原始前端工程与后端工程，核对该提交对应的开发版本；获取配置项名称和部署说明，不把实际密钥提交到仓库。
2. 在隔离的开发环境运行服务，核查数据库类型、持久化位置、现有表、接口返回结构和备份恢复方式。
3. 与周昊确认注册方式、密码恢复方式、登录入口和个人足迹页面；与相关前端同学确认接口字段、错误提示和加载状态。
4. 先完成一个闭环：用户注册登录 → 到访一个节点 → 云端保存 → 换浏览器登录恢复。
5. 加入答题记录、游客导入、收藏；再连接印章状态和个人足迹页面。
6. 联调原有留言和后台功能，验证权限、跨域配置、服务重启后的持久化及备份恢复。

历史内容在线编辑可以后排，不必为了账号功能立即将全部静态史料迁入数据库。后台已有功能先核验和复用，不重新实现一套。

## 7. 验收清单

- [ ] 游客可以正常浏览、答题；拒绝导入不影响浏览。
- [ ] 登录后记录能跨浏览器恢复，服务重启后仍存在。
- [ ] 账号 A 无法读取或修改账号 B 的资料、进度、收藏和私人记录。
- [ ] 普通用户不能调用管理导出、审核、删除、清空接口。
- [ ] 重复到访、重复收藏、网络重试不会造成重复个人记录。
- [ ] 正确与错误作答均可追踪，伪造前端分数不会改变服务端结果。
- [ ] 游客旧记录导入不会冒充服务端已验证答题结果。
- [ ] 多设备更新不丢失记录；取消收藏不会被旧设备的自动合并恢复。
- [ ] 网络失败会显示同步状态，不把“仅本机保存”提示为“云端已保存”。
- [ ] 备份可在测试环境恢复；不在生产环境进行清空试验。
- [ ] 项目可按说明从源码启动、构建和部署；发布产物不包含私密配置。
